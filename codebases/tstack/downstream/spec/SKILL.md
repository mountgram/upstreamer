# Spec

Use this skill before implementation when ambiguity could cause rework.

## Workflow

1. Restate the problem, user, and desired outcome.
2. Define in-scope and out-of-scope behavior.
3. Describe user flows, data changes, API changes, UI states, and error handling as applicable.
4. Identify constraints, risks, migrations, compatibility concerns, and observability needs.
5. Write acceptance criteria that can be verified by tests or manual checks.
6. List open questions only when they block a correct implementation.

## Output

- Goal.
- Scope.
- Proposed behavior.
- Non-goals.
- Acceptance criteria.
- Verification plan.
